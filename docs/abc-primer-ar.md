# السكور و ABC: شرح لمستخدم غير موسيقي

هذا الملف مكتوب لمن لا يقرأ النوتة. الهدف ليس أن تصير عازفًا، بل أن تقدر تنظر
إلى سكور أو ملف ABC وتحكم: هل هذا صح؟ أين المشكلة؟ ماذا يعني هذا الرمز؟

---

## ١) شنو "السكور"؟

السكور = الموسيقى مكتوبة برموز بدل الصوت. كل شيء فيه يقوم على **بُعدين**:

| البُعد | ماذا يمثّل | كيف يُقرأ |
|---|---|---|
| عمودي | **طبقة الصوت** (Pitch): عالٍ/منخفض | موقع النوتة على المدرج: أعلى = أعلى |
| أفقي | **المدة** (Duration): كم تطول | شكل النوتة: معبأة/فارغة/بذيل… |

### عناصر الورقة

| العنصر | المعنى |
|---|---|
| خمسة خطوط (Staff) | "مسطرة" النغمات؛ كل خط وكل فراغ بينهما = درجة |
| مفتاح Sol (𝄞) | يثبّت أي خط يمثّل أي نغمة (نستخدمه دائمًا هنا) |
| البيمولات بعد المفتاح | **المقام** (Key): أي الحروف تُعزف بيمول تلقائيًا |
| `2/4` | **الميزان** (Meter): بار = نبضتان، كل نبضة ربع |
| `♩=84` | **السرعة** (Tempo): ٨٤ ربع بالدقيقة |
| خطوط عمودية | تقسيم **البارات** (Measures) |
| `Fm` / `B♭maj7` | **كورد** (Chord): اسم تآلف هارموني يُعزف مع اللحن |
| قوس بين نوتتين | **ربط** (Tie): النغمة تُمدّ ولا تُعزف ثانية |

### لماذا "بار" مهم؟

البار هو وحدة القياس الزمنية. لو الميزان `2/4` فكل بار لازم يحتوي **بالضبط**
نبضتين. هذا هو أهم فحص في أي ملف: كل بار يجمع المدة الصحيحة أو الملف مكسور.

## ٢) شنو ABC؟

ABC طريقة لكتابة نفس السكور **كنص عادي** — مثل Markdown للموسيقى. اخترناه لأنه:

- قابل للمراجعة بـ`git diff`: ترى بالضبط أي نغمة تغيّرت؛
- دقيق رياضيًا (مدد كسور، بلا تقريب)؛
- مقروء بدون أي برنامج.

الملف قسمان: **رأس** (headers) ثم **جسم** (music lines).

```abc
X:1                     ← رقم المقطوعة
T:                      ← العنوان (قد يكون فارغًا)
M:2/4                   ← الميزان
L:1/32                  ← الوحدة الافتراضية: النوتة العارية = 1/32
Q:1/4=84                ← السرعة: 84 ربع/دقيقة
V: Vocal clef=treble name="Vocal Melody" snm="Vocal"
V: Ins   clef=treble name="Ins Melody"   snm="Inst."
K:Bbm                   ← المقام B♭m (خمسة بيمول)
% مقطع             ← تعليق: يُستخدم لتسمية الأقسام، لا يُطبع
V: Vocal
"Bbm"z16|"Ebm"z16|"Fm"z16|"Bbm"z16|
V: Ins
B8D8|E12D4|F8E8-|E16|
```

هذا هو `examples/demo.abc` بالضبط، وهذا ما ينتج عنه (`examples/demo.png`):
كورد فوق كل بار على ستاف **Vocal** (فاضي/سكتات)، واللحن على ستاف **Ins**.

> **ملاحظة مهمة لأغاني هذا النوع:** ستاف Vocal فاضي ليس خطأ — الكوردات تسكن
> هناك، واللحن المستخرج من التسجيل يوضع على ستاف Ins.

## ٣) جدول الرموز (كل ما تحتاجه)

| الرمز | المعنى | مثال |
|---|---|---|
| `A`–`G` | نغمة في أوكتاف الوسط | `C D E` |
| `a`–`g` | نفس الحرف **أوكتاف أعلى** | `c` |
| `'` / `,` | رفع/خفض أوكتاف | `e'` , `b,` |
| `^` `^^` | دييز، دييز مزدوج | `^F` , `^^C` |
| `_` `__` | بيمول، بيمول مزدوج | `_B` , `__E` |
| `=` | بيكار (إلغاء التغيير) | `=C` |
| رقم بعد الحرف | مضاعف للوحدة `L:` | `e8` |
| `z` | سكتة بنفس قواعد المدة | `z8` |
| `Z` | سكتة **بار كامل** | `Z3` = ٣ بارات |
| `|` | خط بار | `z16|` |
| `-` | ربط بالنغمة التالية (Tie) | `b4-|b4` |
| `"Bbm7"` | كورد | `"Bbm7"z16` |
| `[K:A]` | تغيير المقام وسط القطعة | `[K:A]a24` |
| `% نص` | تعليق / اسم مقطع | `% verse` |

### جدول المدد (`L:1/32`، وبار `2/4` = ١٦ وحدة)

| الرقم | المدة | الاسم |
|---|---|---|
| 1 | 1/32 | أصغر نوتة |
| 2 | 1/16 | |
| 3 | 1/16 منقّطة | |
| 4 | 1/8 (ثُمن) | |
| 6 | 1/8 منقّطة | |
| **8** | **1/4 (ربع)** | النبضة الواحدة |
| 12 | 1/4 منقّطة | |
| **16** | **1/2** | بار كامل في 2/4 |
| 24 | 1/2 منقّطة | |
| 32 | كاملة | |
| 48 | كاملة منقّطة | |

"منقّطة" تعني: **١.٥ × المدة** (نقطة بعد النوتة تضيف نصف قيمتها).

## ٤) تشريح بار حقيقي

خذ هذا السطر:

```abc
z4e'2e'2z8|e'8e'2c'2z4|z12b4-|b8z8|
```

| الرمز | القراءة |
|---|---|
| `z4` | سكتة بمقدار ثُمن |
| `e'2` | نغمة E في أوكتاف أعلى، 1/16 |
| `e'2` | نفسها مرة ثانية |
| `z8` | سكتة ربع |
| `|` | نهاية البار |

المجموع: 4 + 2 + 2 + 8 = **16** = بار 2/4 كامل ✓

ثم في البار الثالث/الرابع:

- `z12` = سكتة ربع منقّطة،
- `b4-` = نغمة B ثُمن **مربوطة**،
- `b8` بعد خط البار = إكمال الربط.

النتيجة في الورقة: **نوتة واحدة طويلة تعبر خط البار**، بقوس فوقها.

ولأن المقام `K:Bbm` فالحروف `B E A D G` تُعزف بيمول تلقائيًا — لا تحتاج كتابة
`_b`، وإذا أردت B♮ تكتب `=B`.

## ٥) كيف تقرأ ملفًا عمليًا (٤ خطوات)

1. **اقرأ الرأس**: الميزان، المقام، السرعة. هذه تحدد "شنو ممكن يكون صح" قبل
   أي نغمة.
2. **عدّ البارات بـ`|` مش النوتات**. لو صوتان في الملف فلازم يكون لهما نفس عدد
   البارات.
3. **داخل البار**: الأرقام = الإيقاع، الحروف = الطبقة، `z` = سكوت. لا تحتاج
   أسماء النغمات، تحتاج **شكل** الحركة: صاعد، هابط، ثابت، قفزة.
4. **قارن مع الرندر**: افتح PDF/PNG وملف ABC جنبًا لجنب. أول أربع بارات تكفي
   لتفهم كيفية الترجمة. الـABC هو "الكود"، والـPDF هو "المخرَج بصريًا".

## ٦) فحص سريع كغير موسيقي

لا يحتاج أذنًا — يحتاج عدًّا:

| العلامة | ماذا تعني |
|---|---|
| بارات `z16` أو `Z` متتالية كثيرة | الموديل ما وجد لحنًا هناك — إشارة ضعف |
| تكرار `z12` / `z8` بلا نوتات | نفس المشكلة |
| قفزات بأكثر من `''` أو `,,` | التباس أوكتاف |
| `-` في آخر الملف بلا إكمال | ربط معلّق = ملف مكسور |
| نفس الكورد ٦–٨ بارات | هارموني راكد |
| مجموع مدد البار ≠ 16 (في 2/4) | خطأ بناء صريح |

الـparser عندنا يرفض أي بار لا يجمع صح، وأداة `verify()` في المحوّل تقارن
مجموع المدد بعد التحويل مع المصدر — أي فقد صامت يُرفض.

## ٧) من ABC إلى ورقة

MuseScore — وأي محرّر نوتة — **لا يفتح ABC**. لذلك المسار:

```
score.abc ──tools/abc_to_musicxml.py──► score.musicxml ──MuseScore──► PDF / PNG / MIDI / MP3
```

مثال:

```bash
python3 tools/abc_to_musicxml.py examples/demo.abc \
    --out /tmp/demo.musicxml --render pdf
```

وإن أردت سماع اللحن بسرعة بدون MuseScore: حوّل إلى `mid` ثم شغّله بأي مشغّل.

```bash
python3 tools/abc_to_musicxml.py examples/demo.abc --out /tmp/demo.musicxml --render mid
tools/mscore-cli -o /tmp/demo.mid /tmp/demo.musicxml   # (--render mid يفعل نفس الشي)
```
